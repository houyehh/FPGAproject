## C. 實作手法的推導

### C.1 報價門檻摺入 readout accumulator

`tau` 為編譯期已知的常數，故

```
W_out·h + b_out >= tau   ⟺   W_out·h + (b_out − tau) >= 0
```

將 `−tau` 摺進 readout accumulator 的初始值後：

- 決策退化為**符號檢查**（讀 MSB），零運算成本
- `tau` 不需儲存，也**不參與量化**
- 省去 comparator：DSP −2、LUT-as-logic −487

**驗證：** 全部 20,852,994 個事件中，摺疊後決策與明確門檻判斷的翻轉數為 **0**。
此為結構上的等價，不是數值近似。

### C.2 定點誤差的來源定位

定點化使每成交損益下降約 2.7 元（佔改善幅度 2.89%）。該損失可能來自輸出量化，
也可能在上游累積，兩者的改善方向完全不同，故做了定位：

| 量 | 值 |
|---|---|
| 分數的定點對浮點誤差中位數 | 4.290 |
| 輸出量化步長 | 0.0432 |
| 比值 | **99.3 倍** |

**誤差比輸出量化步長大兩個數量級，故不是輸出量化造成的。**

逐 channel 分析顯示狀態誤差與 decay rate 的理論放大倍率 `1/(1−|a_i|)` 正相關
（log 相關 r = 0.6958）。最慢的 channel `|a| = 0.9808` 對應放大倍率 **52.0**。

**即誤差集中在記得最久的那幾個狀態上，這是對角遞迴的結構性特徵。**
提高狀態儲存解析度已實測無助（B.2 倒數第四列）：把 `<24,12>` 改為 `<24,5>`
（多 7 個小數位）使保留率由 85.69% 降至 85.11% 並觸發飽和，
**因為誤差在進入狀態儲存之前就已經產生了。**

### C.3 centering 折疊

centering 是一個固定的線性投影 `C = I − (1/h)11ᵀ`，故

```
C(Wx + b) = (CW)x + (Cb)
```

把 `C` 預乘進前級權重後：

- mean 的計算與減法在推論時成本為零（省 2 個 scheduling state）
- 折疊後的向量在構造上 mean 為零，**使 variance 只需要一棵歸約樹，
  不再需要兩棵相減的形式，從而消除 catastrophic cancellation 的失效模式**

浮點折疊誤差 8.88e-16。

### D.1 架構層的任務代價（未在現行口徑下量測）

架構層含兩項改動：對角化，以及容量縮減（h = 16 → 8）。**兩者都有受控的單一變因消融，
但都在本專題早期的評估協定下完成**，故其數值與第三章的框架不同尺。分列如下。

#### D.1.1 容量縮減（h = 16 → 8）：舊協定下已量測，現行口徑下未量測

A.5 的容量消融在本專題早期的評估協定下完成，與第三章的框架有四項差異：

| 項目 | 第三章框架（現行） | A.5 所用協定（早期） |
|---|---|---|
| 目標與 loss | 每側 queue-position maker P&L、normalized MSE | 方向標籤、Huber loss（delta = 1.0） |
| 動作空間 | 雙邊獨立掛單／撤單 | 三選一（掛買／掛賣／不報價） |
| 成交與指標 | queue position 模擬、每成交 maker P&L | **機率成交代理**、序列化超額損益 |
| 狀態處理 | 連續遞迴狀態 + TBPTT | 預建序列張量，各自獨立評估 |

**其中成交模型一項尤其關鍵：該機率代理即附錄 F 所述、經實測低估成交率 3 至 4 倍
而被本專題取代者。**

**現行協定下，只有 h = 8 的部署 seed 完成凍結門檻的 OOS 評估；h = 16 無對應結果，
h = 8 的另外兩個 seed 亦只有訓練 checkpoint 而無完整 OOS。** 故「容量縮減不付任務代價」
在現行口徑下為未驗證項目。

**解除方式：** 以 11B 的完整協定訓練 diagonal h = 16（三 seed），並補齊 h = 8 另外兩個
seed 的凍結門檻 OOS 評估。h = 8 的三個 checkpoint 已存在，故後者只需評估不需訓練；
前者依 11B 的實測（約 450 輪、每輪 20.6 至 21.4 秒、每 seed 約 2.6 小時）估計為單機數小時量級。

#### D.1.2 對角化：已有受控消融，但在舊協定下

**對角化的任務代價已由受控消融量測**（報告 §5.2）：對照組為同一架構的 dense 版本，
hidden dimension、seed 數、訓練輪數、patience、batch size、學習率與其排程、weight decay、
特徵集、標籤與成交設定全部固定，**唯一變因是遞迴的結構**。三個 seed 的結果為
保留率 86.63%／90.82%／88.52%，即代價 13.37／9.18／11.48 個百分點，三切分平均 11.34。

**一項曾經的誤判，記錄於此。** 報告早期另引用過一個 13.72 pp 的數字，並一度認為它與
總結中的 11.13 pp 互相矛盾而撤回了整個宣稱。**兩者其實一致：13.72 是驗證集單一 seed 的值，
11.13 是三切分平均（與本節的 11.34 同量級）。** 真正的問題只是從未標明各自的母體，
而非數字有誤。

**仍然成立的保留只有一項：該消融在本專題早期的評估協定下完成**（action P&L、機率成交代理、
方向標籤），與第三章的框架不同尺，未重做。**但因兩組條件完全相同，其差值仍是對角化的代價；
不確定的是該代價換算到現行口徑後的絕對大小，而非它是否存在。**

**另一項無法量測的事。** 若要在現行協定下重做，須先有一個現行協定下的 diagonal h = 16 基準
（見 D.1.1），而該基準目前不存在。本專題曾規劃以「只替換狀態轉移」的方式在 h = 8 上重做，
前置核對發現現有的 h = 16 對角基準本身即在舊協定下，故該路徑被同一個問題擋住。

**在現行協定下重做的實測成本。** 之後以現行協定（11B 訓練 ＋ 16A 評估）重做同一對架構的前置量測已完成：
部署 seed 的數值重現、參數量（dense 1,731／對角 370／對角 h = 8 為 186）與單一變因核對皆通過。
但一個 epoch 的實測時間為 **dense 1,760.9 秒、對角 12.0 秒（約 147 倍）**——對角的線性遞迴可用
associative prefix scan 一次算完整段，dense 的非線性遞迴只能逐事件迴圈。以 500 輪上限計，
dense 單一 seed 最壞約 245 小時，三個 seed 約 734 小時，超過預先登記的 12 小時停止條件，故未執行。
**對角化在訓練端也有這項成本差距，但其任務代價在現行協定下仍未量測。**

### D.2 容量不增益的機制（未驗證）

A.5 量到 h = 16 相對 h = 8 在兩個凍結測試集上無可偵測的任務品質差異。

**一個可能的機制：** 對角狀態空間模型的每個 state channel 是一個帶自學 decay rate
的指數移動平均，其容量近似於「可追蹤的相異時間尺度數」。本模型實測的 time constant
範圍為 1.61 至 51.96 個事件。若市場訊號只有少數幾個有意義的時間尺度，
多給的 channel 可能只是複製已有的 decay rate。

**要驗證需比對 h = 16 模型的 decay 向量是否出現重複的 time constant。
本專題未做此量測，故該機制僅為解釋，不作為結論。**

### D.3 往後掛的掃描（母體受限）

早期的退檔掃描為**兩時段的 pilot**（`pilot_scope: pilot_two_sessions_only`），
而 d ≥ 1 的三列僅來自單一時段 `val/20260126Night`：

|---:|---|---:|---:|---:|---:|---|
| d = 0 | val/20260126Night | 10,794 | 196.29 | −89.46 | **+106.84** | — |
| d = 1 | val/20260126Night | **285** | 376.49 | −510.18 | −133.68 | **underpowered** |

**d ≥ 1 的成交數為 285／44／12，全部被管線標記為 underpowered，
故這三列只能視為指標，不構成結論。**

**報告 §3.4 不使用此表**，「不採用退檔」的決定由兩項母體完整的證據支撐：

1. **理論論證：** 若往後掛是免費的錢，競爭者都會往後掛，均衡價差會持續變寬
   直到它不免費為止。故往後掛的超額報酬在均衡下應為零或負。
2. **完美預知對照（12 組態、全切分）：** 完美退檔使每來回 mark movement 由
   −326.80 元改善至 −52.8 至 −78.7 元（11／12 組態獲利），而完美撤單
   改善至 **+82.5 至 +86.3 元（12／12 組態獲利）**。
   **撤單把 adverse selection 由成本轉為收益，退檔只是把它變小。**

**若要把退檔作為結論，需在全部 16 個時段上重跑掃描。**

## E. 閘門設計的教訓

本專題大量使用預先登記的判定閘門——在跑之前固定判準，避免事後移動門檻。
該方法有效，而其失效模式集中於一處：**門檻被寫在與被判定量不同的尺度上。**

**一、跨量綱比較。** 以「單次擾動按 decay rate 消退」的包絡 `max|a|ⁿ` 判定連續注入誤差，
七個變體全數被判為失敗——包含一個任務品質 99.38% 的通過變體。成因是連續注入誤差的
穩態上界為 `ε/(1−|a|)`，於 `|a| = 0.9188` 時為 12.31ε，必然高於單次擾動的衰減包絡。

**二、閘門窄於抽樣噪音。** 為驗證「無差別報價的毛邊際為零」，設容忍為 ±0.5 元，
而該統計量在 n = 82,960 下的標準誤約 0.52 元——閘門約等於一個標準誤。
改以改以交易時段為單位檢定後 t = 1.063，遠低於臨界值。

**三、比率在分母趨零時不穩定。** 以「drift 分量／毛邊際」的比率設 10% 門檻，
而配對隨機策略的毛邊際依定義趨近於零（實測 −0.00737 元），使其比率達 143.57%。
正確的寫法是絕對值門檻。

**四、對連續量的 argmax 要求位元相同。** 以「報價門檻是否改變」作為是否重建資料的判準；
移除 6.173% 的重複決策後門檻由 1516 移至 1511——分數跨距 6,350 之 0.08%，
而該門檻本就是從連續掃描取分位數的 argmax。

**五、以「early stopping 是否觸發」作為「資料是否足夠」的代理。** 等預算 TCN 的
seed0 於 137 輪收斂，seed1 跑滿 500 輪仍「在改善」——但兩者最終 val loss 僅差 0.15%。
成因是 cosine annealing 下學習率持續下降，小模型每輪改善 1e-6 也算改善，
patience 計數器永不滿。改為「連續 20 輪的相對改善 < 0.1%」後正常。

**六、重現閘門只能抓重構錯誤，抓不到既存錯誤。** 為新增第三個撤單規則而重寫模擬器時，
閘門要求重現既有兩個端點的數值——該閘門通過，而既有的一項**解釋**（比例規則會自我衰減）仍是錯的。**數值可重現不代表其解釋正確。**

**七、母體標示。** 數次把 pilot 範圍的結果寫成全母體
（退檔掃描為兩時段 pilot、§4.6 的舊數值來自重訓前的模型）。
**這類錯誤不會讓任何閘門失敗**，因為計算本身正確，錯的是歸屬。

**八、閘門判為不可宣稱，而正文仍在宣稱。** 隨機選側撤單的對照其預先登記閘門要求
成交率匹配，實測未匹配（隨機對照的成交數比模型多 54.76% 至 205.22%），審計判定為
`cannot_claim`，且時段層級檢定僅 6／12 達顯著。**但報告正文一度仍以該對照宣稱
「價值在於撤對邊」。** 此為最危險的一類失誤——**不是沒做對照，而是做了對照、對照否決了宣稱，
而結論未隨之修改。** 外部審稿在核對 `AUDIT_RANDOM_SKEW_CONTROL.md` 後指出此事，正文最終移除了該對照；
其結果與審計判定列於 repo 的 README。

**有效的閘門須先回答四個問題：這個量的單位是什麼、它的抽樣噪音有多大、
它的分母會不會趨零、以及它算在哪個母體上。而閘門判定之後還有第五個問題：
正文的宣稱有沒有隨著判定一起改。**

## F. 已被取代的評估基礎設施

本專題早期以一個成交機率代理決定成交：

```
depth = 1 / (1 + top_depth / top_depth_median)
side  = 1 / (1 + 本側深度 / 本側中位數)
p     = clip(0.5 · depth · side, 0.01, 1.0)
```

中位深度下 `p = 0.5 × 0.5 × 0.5 = 12.5%`。

**該係數 0.5 的出處：** 本專題早期的委託簿壓力測試，為「中度壓力」的
`fill_keep_rate` 檔位設定。該階段的報告開宗明義聲明其**不實作 true queue replay、
aggressor-side replay 或 order-ID level matching**。

**即：一個壓力測試的乘數後來被當成成交機率使用。**

**實測對照：** queue position 模擬的掛於最佳價成交率為 35.48% 至 49.35%（三個規則），
而該代理給出 12.5%——**落在真實區間之外，低估約 3 至 4 倍。**

此為本專題改以 queue position 模擬的直接原因。

## G. hls4ml 轉換嘗試的詳細紀錄（§5.5）

五個模型變體於 hls4ml 1.3.0（另以 1.4.0.dev32 測試）全部止於模型解析階段。

| 阻擋點 | 說明 |
|---|---|
| 二維 LayerNorm 形狀限制 | 遞迴步內的 LayerNorm 形狀不被 PyTorch 前端接受 |
| `ConstantPad1d` 形狀解析 | 前饋 TCN 變體於此失敗 |
| `torch.fx` 無法追蹤 | 含控制流的 forward 無法被符號追蹤 |
| ONNX 匯出路徑 | 亦未通過 |
| 無對應 layer type | 對角狀態空間模型在 hls4ml 中沒有對應的層 |

**阻擋與遞迴本身無關：** 前饋的 TCN 同樣被阻擋；hls4ml 自 Khoda 等人（2023）起即支援
LSTM 與 GRU，自 1.2.0 起於 Vivado 後端支援 LayerNormalization。**問題發生在 PyTorch
前端的模型解析，而非遞迴的硬體生成。**
